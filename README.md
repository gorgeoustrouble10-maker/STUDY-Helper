# 个人数字花园

公开博客、私密工作台和独立的内容发布流程。默认中文、上海时区，业务数据保存在本地 SQLite，附件保存在受控数据目录。

**当前为已完成本地验收的可运行版本。** 依赖锁定、初始迁移、类型检查、生产构建、单元/集成测试（12/12）与双端 E2E（桌面+手机）均已通过，实际验证状态与证据见 [验收报告](docs/ACCEPTANCE.md)；遗留限制（dev 模式 HMR、Docker 未执行等）也记录在该报告中。接手开发请阅读 [交接文档](docs/HANDOFF.md)。

## 本地启动

需要 Node.js 24 和 npm。依赖锁文件与初始迁移准备完成后的首次运行：

```powershell
npm ci
npm run setup
npm run owner:init
npm run dev
```

首次使用建议复制 `.env.example` 为 `.env`，并保证 `SITE_URL` 与浏览器实际访问地址完全一致（来源校验做精确匹配；生产模式 `npm start` 必须设置，否则登录会返回 403「请求来源不正确」）。

打开 http://127.0.0.1:3000。`owner:init` 交互创建唯一所有者，密码至少10个字符、输入隐藏。没有默认生产账号或公开注册。此命令不会覆盖已有所有者。

`setup` 创建数据库并准备九个领域、七门课程、六个项目/专题和明确标记的示例内容。再次运行不会覆盖已编辑的记录，也不会重新公开已撤回的示例。示例文章、作品、花园笔记和推荐可以在“写作与发布”中编辑或撤回。

## 数据位置与配置

默认数据目录为工作目录下的 `.data`，可通过 `DATA_DIR` 指定绝对或相对目录。数据库为该目录中的 `garden.db`，私密附件在 `uploads`，公开版本附件在 `published`。数据库 URL 的自动配置用于 CLI 和应用；设置 `DATABASE_URL` 时请在两者中保持相同的绝对文件路径。

`SITE_URL` 指定浏览器访问的站点来源，用于 SEO 和来源校验；`SESSION_DAYS` 默认7天。参考 `.env.example`。Next.js 会读取 `.env`；独立 CLI 推荐在 shell 设置环境变量，或沿用默认目录。

时间以 UTC 存储，页面和日期输入使用上海时间。财务使用人民币，以整数分存储金额；第一版提供手动收支、账户与分类预算，不包含银行连接、外汇或复式会计。

## 完整使用流程

1. 在“收件箱”或“快速记录”写下想法，只需标题与正文。
2. 编辑记录，关联领域、课程或项目。关联不会复制正文。
3. 从项目、课程或记录详情建立行动，分别设置计划、真实截止和提醒时间。今日重点和本周承诺由自己选择。
4. 完成行动；重复行动会创建一次后续实例。月末的每月重复夹到下一月末。
5. 建立复盘，关联证据并点击“保存关联记录快照”；后续修改不改写快照。
6. 选择“整理公开稿”，再编辑面向读者的表达。独立选择公开附件，移除内部引用。
7. 预览、发布。内部原记录和后续草稿修改不会改变当前公开版本。

公开：首页、关于、作品、文章、成长花园、推荐、连接、主题、搜索、归档、RSS和站点地图。

工作台：今日、收件箱、行动、项目、问题、领域、课程、知识、复盘、写作、人物、物品、财务、归档、回收站、设置。

## 保存与版本

首次手动保存后开启自动保存。输入在浏览器有编辑恢复副本，业务数据仍以服务器为准。跨窗口修改触发409冲突，保留输入并展示远端版本，需手动选择处理方式。编辑历史可恢复为草稿。

归档保留数据；删除进入回收站；撤回移除公开访问。删除项目不会删除关联笔记。已有收支的账户必须先处理有效交易才可删除。财务汇总纳入已归档但未删除的交易。

内部正文支持 `[[记录ID]]` 引用。公开稿中须整理为独立表达或公开链接，发布会阻止内部工作台地址与未选择的私密附件进入正文。恢复旧发布版本时重新创建私密附件副本，之后可以再次预览与发布。

## 附件与权限

支持不超过10MB的JPG、PNG、WebP、GIF、PDF、纯文本。通过工作台上传，图片可插入正文。私密附件逐请求鉴权，公开附件是独立复制的版本，只在对应版本当前公开时可访问。没有可执行的MDX或任意HTML渲染。

唯一所有者使用带随机盐的scrypt密码哈希；数据库只保存会话令牌哈希。修改请求校验来源，登录提供全局所有者限速。设置中的“公开个人信息”会直接用于公开页面，请在那里只填写适合公开的介绍、联系方式和链接。

## 备份与恢复

工作台设置中可下载完整 ZIP 备份及 Markdown 导出，并上传备份进行独立目录恢复验证。备份包含业务记录、附件、关联、编辑历史和发布版本，不包含密码、会话或密钥。

```powershell
npm run backup
npm run restore -- backups\备份.zip .data-restored
```

恢复目录必须为空，不能覆盖现有数据库。核对恢复结果后，将 `DATA_DIR` 指向新目录、初始化所有者并重新启动即可使用恢复数据。网页恢复验证会保存到当前数据目录下的 `restored/随机标识`，不会切换当前使用的数据库。

迁移后的备份与实际恢复结果都应保留。自动保存不是备份的替代。

## 生产构建与 Docker

```powershell
npm run typecheck
npm run build
npm start
```

```powershell
docker compose up -d --build
docker compose exec garden npm run owner:init
```

Compose仅绑定本机3000端口，数据通过命名卷持久化。公网部署前需提供域名与部署环境，再配置HTTPS、反向代理、`SITE_URL`及备份。不要删除数据卷作为常规升级步骤。

## 检查与测试

```powershell
npm test
npm run test:e2e
```

单元/集成测试在独立 `.test-data` 目录运行，覆盖冲突、重复行动、发布隔离、附件快照、复盘快照、中文检索、财务精度和备份恢复。

浏览器测试需要在3001端口运行测试数据实例，并在环境中提供测试账号。运行配置见 `docs/TESTING.md`；报告见 `docs/ACCEPTANCE.md`。测试不会创建生产默认账号。

第一版不包含外部消息提醒、多人协作、通用离线编辑、银行连接、AI服务或其他项目代码改动。提醒时间会在今日安排中出现；浏览器界面提供核心记录、编辑、复盘、预览和发布操作。
