# Android 0.2.0：AI 分析能力接入

日期：2026-10-21。本轮继续完善 MVP，不代表已与网页版完整对齐。

## 新增范围

- “我的 → AI 助手”；记录详情可携带该记录进入 AI 页面。
- 中文多轮会话，云端保存历史，手机按账号缓存已打开的历史，离线可阅读缓存。
- 每次最多选择 3 条已同步且未归档的参考记录；云端工具可搜索本人记录、读取正文、查询今日行动和本月收支。正文和查询数量有限制，并向模型标明截断。
- 请求使用固定 requestId，网络中断后可恢复原请求；服务端每用户一个在途请求、全局最多两个，含频率、工具次数、响应长度和总耗时限制。
- 支持停止生成；取消后迟到的模型回复不能成为正式回复。服务重启将未完成请求标为失败，保留已发送的问题。
- 回复可转为笔记草稿，进入编辑器后由用户确认保存。AI 没有业务写入工具，不会直接修改或删除记录。
- 不复用旧网站所有者登录态；所有会话、工具读取和参考记录按当前移动用户隔离。密钥只在服务端。

## 模型配置状态

初次检查时，云端旧网页的 AI 未启用且缺少模型及密钥。随后用户提供 DeepSeek 配置，现已在移动服务的服务器私有环境文件启用 `deepseek-chat`。提供商密钥未写入源码、APK 或本地配置文件。旧网页的 AI 配置未随本轮改动。

在服务器私有 `/etc/study-helper-mobile.env` 中配置 `MOBILE_AI_ENABLED=true`、`MOBILE_AI_PROVIDER`、`MOBILE_AI_MODEL`、`MOBILE_AI_BASE_URL`、`MOBILE_AI_API_KEY` 后重启移动服务。变量样例见 [API 配置](../services/mobile-api/.env.example)。云端提供商需要密钥，Ollama 可使用服务器可访问的本地模型地址。不要在 Android 客户端填写或保存提供商密钥。

自动化测试使用可注入的模拟提供商验证隔离与故障处理；另已通过公网 HTTP 完成真实 DeepSeek 验收：搜索并读取临时账号云端笔记、校验随机暗号和参考记录、原请求幂等重试、携带参考记录继续会话、取消后无迟到正式回复。测试账号、记录、会话和关联操作已清理。真实手机界面操作仍未执行。
