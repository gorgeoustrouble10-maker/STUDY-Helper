## 已通过项的运行细节

### E2E 覆盖场景（tests/e2e/garden.spec.ts，desktop + Pixel 7 双项目）

1. 课程实验：创建行动、关联课程并完成，课程与全局视图一致
2. 博客项目：记录关联笔记与复盘，保存当时证据
3. 资源成为推荐：创建公开稿、发布、验证阅读、撤回
4. 访客不能读取内部记录、预览和私密附件
5. 登录失败与空标题保存都有明确提示
6. 两个窗口同时编辑，旧窗口保存遇到 409 并保留输入
7. 断网时自动保存失败保留输入，重新打开可恢复未保存草稿
8. 键盘可以完成输入、字段切换与保存
9. 移动端可以打开与关闭导航（仅 mobile 项目）
10. 真实上传的附件匿名不可读取，所有者可读取
11. 发布稿的公开附件在撤回后立即失效
12. 内部资源整理为公开推荐，公开页不泄漏内部来源
13. 复盘证据快照不随后续修改变化

测试实例：`DATA_DIR=.test-data/e2e`，生产模式 `next start -p 3001`，QA 所有者通过 `INIT_OWNER_USERNAME`/`INIT_OWNER_PASSWORD` 环境变量非交互初始化（账号见 docs/TESTING.md，仅存在于隔离目录）。报告：`playwright-report/`；失败 trace：`test-results/`。

### 公开边界核查方法与结论

以「所有未公开记录的标题 + 正文前 40 字符」为私密样本，请求 10 个公开入口（首页、关于、作品、文章、花园、推荐、连接、RSS、站点地图、公开 API）。原始扫描命中 43 处，逐一甄别：

- 「学习/工作/写作/身体」等单词命中：与公开页面自带的领域分类导航文案重合，非数据泄漏；
- 「正文包含公开附件说明」等命中：E2E 多条测试记录共享同一测试正文，文本实际来自**处于已发布状态的那条记录的公开正文**（撤回/草稿状态的相同文本是另一条独立记录），非私密记录泄漏；
- 排除上述两类后最终 **realLeaks=0**；
- 正对照：4 个公开列表页均正常展示 6 条已发布内容（证明扫描方法有效，不是恒假阴性）；
- 公开 API 返回字段为 title/body/slug/type/summary/tags/details/id/publishedAt/assets，无内部字段。
