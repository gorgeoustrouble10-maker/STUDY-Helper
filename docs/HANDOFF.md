## 2. 用户目标与已经确定的边界

用户要一个整体网站：对外展示个人作品、思考、成长与推荐的博客，对内管理成长、生活、行动和复盘的私密工作台。网站具有安静、温暖、有个人辨识度的数字花园气质。

首版只供本人使用，为以后协作留下合理扩展空间，但现在不开发多人协作。电脑与手机均须完整操作核心流程。界面默认中文，显示上海时间，数据库时间保存为 UTC；财务默认人民币，以整数分存储。

### 公开端

首页、关于、作品、文章与观点、成长花园、我的推荐、连接，以及公开搜索、主题/标签、归档、RSS、站点地图、分享信息和不存在页面。

首页应帮助读者理解身份、关注主题、代表作品、近期写作、持续成长与联系途径。审美贯穿全站；技能连接作品证据；推荐说明适用对象、理由与局限。姓名、头像、联系方式、观点与经历均等待用户填写，不得编造为用户的真实信息。

- “资源成为推荐”E2E 当前直接创建公开稿，**没有真正验证收藏资源 → 整理独立推荐 → 保留来源关联**；必须补成真实链路。

- 备份恢复测试已检查数量及排除部分认证内容，但数量一致不足以证明正文、关联、修订和附件字节完整；补充恢复后逐项核对。
- 现有重复行动测试覆盖完成接口与并发重复请求；补查通用保存改为 DONE、重新打开后再次完成、截止日期与子任务场景。

### 接手后重点复现和评估

- 自动保存失败、两窗口 409、恢复副本、版本恢复：用户输入必须保留，显示可理解的比较与选择。
- 发布、更新、撤回、旧版本恢复：所有公开入口及附件一致，内部关联标题、未选择附件、私密路径不得泄漏。
- 公开稿的 `featured` 字段已定义，首页是否实际依此筛选需核对；此前实现主要取各类内容前几条。
- 某些浏览器选择 txt/md 时 MIME 可能为空；当前上传类型白名单会拒绝，应安全识别或提供明确错误，不能简单放开任意文件。
- 月末重复会夹到下一月末；当前计算只以上一次日期为基准，1 月 31 日 → 2 月 28 日后可能变成 3 月 28 日。明确产品规则并记录，必要时保留原始周期锚点。
- 个人资料设置、标签改名/合并的并发与记录版本一致性；它们没有完全复用正文保存版本机制。
- 登录限速的计数检查与更新在并发请求下是否仍有效；异常存储哈希、过期与注销会话是否安全处理。
- 上传/发布/导入先写文件再写数据库或子进程失败时的恢复、错误反馈和孤立文件；不要让失败处理破坏现有数据。
- 数据恢复输入的路径、数量、体积与关联有效性；确保恢复目标为空且不会覆盖生产数据。
- 编辑弹窗的焦点、关闭、键盘操作、滚动和手机视口；重要功能不可依赖悬停或拖拽。
- 数据较多时客户端全量加载多页记录的性能；先保证检索分页准确，不为优化而截断关联数据。

## 8. 必须执行的验收矩阵

| 维度 | 最低检查 |
| --- | --- |

| 编译 | typecheck、生产 build、生产启动 |
| 认证 | 匿名工作台/API/预览/附件拒绝；登录、退出、过期、限速、来源校验 |

| 问题与复盘 | 事实/假设/尝试/结果分别保存；快照不被后续编辑改写；建立后续行动 |
| 编辑 | Markdown/公式/代码/附件；失败恢复；409 保留输入；历史恢复 |
| 发布 | 独立草稿、预览、发布快照、更新、撤回、恢复；全部公开入口不泄漏 |

| 检索与生命周期 | 中文、标签/别名、分页、归档、回收站、恢复、非级联删除 |
