# Android 客户端代码开发规划

日期：2026-10-21。本文保留最初的完整开发设计与验收计划，不表示所有功能已经实现。当前已交付 0.1.0 MVP，并继续开发 0.2.0；实际状态以 [功能完善路线](ANDROID-ROADMAP.md) 与版本交付记录为准。下文目录和接口部分仍包含目标设计。

## 1. 确定目标

- 交付可直接下载、安装和升级的签名 APK，独立运行，不依赖 Expo Go 或开发电脑。
- 多用户注册、登录；注册填写邀请码，服务端只有在 `LOVEXCZ` 匹配且其他注册条件通过后创建账号。正确邀请码不写入客户端逻辑或表单提示。
- 全部业务记录同步到云端；手机保留离线副本、未同步修改及附件上传任务。
- 主题、字号、设备偏好和缓存仅本地；账号资料、公开个人资料等业务设置同步云端。
- 保留现有中文、上海时区、Markdown、精确金额和独立发布快照规则。
- 云端地址按用户最新要求使用 `http://121.43.32.47`；客户端在本机构建，不进行模拟器安装验证。

技术方案采用 React Native + TypeScript，使用 Expo 工具链和 Expo Router。Expo 是开发与构建方案，用户无需使用 Expo Go。工程建立时选择匹配的稳定 Expo / React Native / React 版本并锁定依赖，不把网站 React 版本强行套到移动工程。

## 2. 页面结构

使用底部五个入口，记录详情、编辑器和搜索放入上层导航栈；全局提供快速记录按钮。保留数字花园的暖色与安静气质，重新实现适合触摸和手机键盘的布局，不照搬网页侧栏。

| 入口 | 主要页面 | 第一轮实现 |
| --- | --- | --- |
| 今日 | 今日重点、安排与截止、阻塞等待、本周承诺 | 今日概览、快速新建、行动完成 |
| 行动 | 列表、状态筛选、详情、编辑、父行动、重复频率 | 新建/编辑/完成、计划和截止时间 |
| 工作区 | 项目、课程、领域；各自的关联行动/资料/复盘 | 项目/课程列表与详情、关联记录 |
| 笔记 | 收件箱、笔记、资源、搜索、标签 | 快速记录、Markdown、收件箱整理 |
| 我的 | 账号、设备设置、同步中心、归档、回收站、更多业务 | 登录状态、同步状态、主题字号、退出 |

认证页面独立：欢迎/登录、邀请码注册、会话失效提示。第一轮注册包含账号、密码、确认密码、邀请码；邀请码只用于注册。

后续页面覆盖现有问题总表、复盘、写作、人物、物品、财务与渠道稿件。它们是完整迁移范围，分阶段交付而非删除功能。普通用户公开发布权限仍待产品规则确定，在规则确认前不展示可执行的发布入口。

## 4. 数据流：从第一天支持本地存储

```text
页面 → 业务命令 → SQLite 事务（业务数据 + 待同步操作）
                       ↓ 本地更新通知
                     页面刷新

同步调度器 → 待同步队列 → 云端 API → 确认/变更/冲突
                                      ↓
                              SQLite 事务应用结果
```

页面业务列表与详情统一读取 SQLite，避免一部分页面读网络、一部分读本地而产生两份业务状态。React 本地状态负责表单输入、弹窗和筛选；首期不额外建立第二份完整业务缓存。

建议本地表：records、类型专用数据、tags、record_links、attachments、drafts、outbox、sync_state、conflicts、file_jobs、device_settings、schema_migrations。按实际查询选择规范化字段和索引；status、kind、updatedAt、关联目标等常用筛选不靠扫描全部 JSON。

用户数据库与附件目录按服务端稳定 userId 隔离。账号切换时停止旧账号同步任务、关闭旧库并卸载旧页面状态；延迟返回的旧请求不得写入新账号库。

业务修改与 outbox 在同一事务提交。新建记录使用客户端 UUID；本地编辑次数与服务端 version 分开。已发出的操作载荷保持不变，后续修改排队，以已确认版本串行提交，避免旧响应覆盖新输入。离线创建后建立关联或添加附件也需遵循依赖顺序。

新账号首次使用需联网注册/登录；曾成功登录的设备可以离线打开本地资料并编辑。凭据失效时停止云端请求、要求重新认证，并保留未同步输入。只有重新认证后才继续向对应用户上传。服务端撤销设备状态只能在设备联网后获知，不能承诺离线实时撤销。

## 5. 同步实现拆分

1. **本地写入**：持久化记录与 operationId，显示“已保存到手机，待同步”。
2. **提交操作**：按依赖顺序发送待处理操作；同一用户只运行一个同步循环，重试复用 operationId。
3. **增量拉取**：使用服务端游标分页拉取记录、关联、历史元数据和删除标记。游标在事务成功后推进。
4. **应用远端版本**：无本地待提交修改时正常更新；存在本地修改时保留其副本，不能直接用拉取结果覆盖。
5. **冲突处理**：保存本地内容、基础版本及远端内容；提供比较后合并、采用远端、保留为新副本。涉及删除/恢复的冲突有单独提示。
6. **异常恢复**：超时与网络错误退避重试，认证失败只触发一次凭据刷新，权限错误进入待处理状态，单条非法操作不能阻塞全部同步。
7. **重新同步**：游标过期、恢复备份等情况下拉取新基线，先保全 outbox 与冲突副本，不能清空未确认修改。

触发时机为启动、回到前台、网络恢复和手动同步；后台任务后续增强，不以后台持续运行作为数据正确性前提。同步中心显示待上传数量、冲突、最后成功时间及可理解的错误，普通页面只显示简洁状态。

网页端、脚本和移动端的所有云端业务写入都必须更新同一变更日志；否则手机无法增量获知网页修改。重复行动后继、复盘快照和发布快照继续由服务端按规则确定，客户端展示待确认状态，不能自行生成一套不同结果。

## 6. 后端接口契约依赖

下列为拟新增协议，不是当前已经存在的接口：

| 能力 | 接口示例 | 客户端关注点 |
| --- | --- | --- |
| 注册 | POST /api/v1/auth/register | inviteCode 必填，按错误码展示结果，不在本机判断正确答案 |
| 登录/刷新/退出 | POST /api/v1/auth/login、refresh、logout | 用户身份、凭据到期、设备撤销、刷新并发控制 |
| 当前用户 | GET /api/v1/me | 服务端稳定 userId、用户资料、能力权限 |
| 首次/增量读取 | GET /api/v1/sync/pull | 有界分页、一致的基线边界、变更游标、删除标记 |
| 提交变更 | POST /api/v1/sync/push | 幂等键、基础版本、逐操作确认/冲突/失败 |
| 文件上传/下载 | /api/v1/files | 归属校验、文件 ID、大小类型校验、可恢复重试 |
| 编辑历史 | /api/v1/records/:id/revisions | 历史可按需读取，恢复作为新业务变更 |
| 发布命令 | /api/v1/publications/:id/... | 在线显式操作、预览版本校验、独立公开快照 |

客户端不提交可信 userId 来选择归属；服务端以认证身份决定范围。设备设置不进入业务 push 协议。接口返回业务状态与错误码，不能让页面解析服务端中文错误文本推断逻辑。

后端未就绪时，先使用开发专用适配器按同一契约开发页面和同步测试；模拟注册成功不算真实注册验收，正式构建禁止启用模拟模式。云端已有版本与本地不同，后端接口实现前先核对代码差异。

## 7. 认证、附件与编辑器细节

### 认证

- access token 尽量仅存内存，refresh token 使用 SecureStore；不把密码、邀请码或凭据写入业务数据库及日志。
- 注册和登录必须联网，邀请码只在注册请求中提交。收到服务端错误时保留账号等非敏感输入，不回显密码或邀请码。
- 退出前检查未同步数据；选择继续同步或保留在当前账号隔离区，重新认证后可恢复。不能静默丢弃或带入其他账号。

### 附件

- 使用系统文件/照片选择入口。文件选中后将待上传原件复制到持久目录，不能长期依赖临时 content URI 或可清理缓存路径。
- 上传任务独立持久化，可重试、显示状态；确认后记录服务端 ID，再同步其业务引用。
- 私密下载携带认证；新建账号无法沿用另一账号下载任务与缓存路径。
- 缓存清理只删除可重新下载的副本，保留上传失败的原件。首期不承诺分片断点续传。

### 编辑器及数据规则

- 原生多行输入框 + Markdown 工具栏 + 预览，正文源文本保真保存；第一轮覆盖标题、正文、标签、关联和业务字段。
- 关闭页面、App 被终止后能恢复本地草稿；保存旧响应不能覆盖之后的输入。
- 数学公式和复杂表格保留源文本，完整渲染安排在内容能力补全阶段；Web 端 react-markdown 不能直接作为原生渲染器使用，需单独验证选型。
- UTC 存储、上海时间显示；金额使用整数分，输入保留文本后严格转换。筛选和搜索本地分页，不复制现有网页全量加载方式。

## 9. 必须验证的风险场景

- 用户 A 无法在账号切换后看到或同步用户 B 的数据；接口也不能跨用户引用记录及附件。
- 创建成功但响应丢失后重试，不重复创建账号业务记录、重复行动后继或附件。
- 同步途中继续编辑、强制结束 App、重启后，记录与队列一致。
- 两设备改同一记录，客户端可比较并处理冲突；删除后离线设备重连不擅自复活记录。
- 飞行模式下编辑/建关联，重新联网后引用和附件正确上传。
- token 到期或设备被撤销后停止提交；重新认证不丢草稿。
- SQLite 升级失败保留原库，安装新版本保留未同步操作；卸载重装仅恢复已同步云端数据，不能承诺恢复未上传修改。
- 真机检查软键盘遮挡、系统返回键、字体放大、日期输入、长列表和大附件；模拟器通过不能替代真机。

测试重点放在仓储事务、同步状态机、认证刷新和用户隔离，组件验证覆盖注册错误、保存状态和冲突处理；再以真机端到端跑核心链。模拟服务、真实测试后端和生产验证结果分别记录。

## 10. 范围与交付物

本规划不引入社交通讯、多人协作编辑或通用云推送。后续已按用户要求接入 AI 分析会话，0.2.0 支持查询本人记录及回复转笔记草稿；AI 工作模式和与网页端完整对齐继续按 [完善路线](ANDROID-ROADMAP.md) 推进。模型密钥始终留在后端。

交付物包括：apps/mobile 源码、共享契约、客户端 SQLite 迁移、环境变量样例、独立检查与测试脚本、构建说明、签名 APK、版本及升级说明、实际测试报告。生产密钥、签名私钥和服务器凭据不进入 Git。
